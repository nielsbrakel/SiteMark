# SiteMark — Decision log

Decisions from the kickoff interview ("grill me" session), written as short ADRs.
Each decision has an ID (`D-###`) that the spec and plan refer to. To change a
decision, add a new entry that supersedes the old one; don't edit history.

| ID    | Topic               | Decision                                                                                                                                                                                       | Why / trade-off                                                                                                               |
| ----- | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| D-001 | Name                | **SiteMark**                                                                                                                                                                                   | Short, says what it does (mark a site), and fits the bookmark-ribbon logo. Alternatives are listed below.                     |
| D-002 | Browsers            | Chromium (Chrome, Edge, Brave, Opera, Arc) + Firefox + Safari in v1                                                                                                                            | "All major browsers". Safari needs a macOS/Xcode build step (see D-015).                                                      |
| D-003 | Framework           | **WXT** (Vite-based) + React 19 + TypeScript                                                                                                                                                   | Cross-browser MV3 builds, HMR, zip/submit tooling, first-class React module. Fits the React/Vite preference.                  |
| D-004 | Manifest            | Manifest V3 for every browser (Firefox ≥ 140, Safari ≥ 17)                                                                                                                                     | One manifest shape. `optional_host_permissions` in Firefox needs 128+; `data_collection_permissions` needs 140 (current ESR). |
| D-005 | Element selection   | Visual picker (hover + click) that generates a stable CSS selector, which stays **editable**                                                                                                   | Easy for everyone, with a fallback for power users when a generated selector breaks.                                          |
| D-006 | URL matching        | Wildcard patterns (`https://*.example.com/*`) by default, optional **regex** as an advanced mode, plus a live "does this URL match?" tester                                                    | Wildcards cover 95% of cases and map cleanly to browser permission origins.                                                   |
| D-007 | Marker styles       | All of: corner ribbon, outline + tint, page banner/frame, and the extras (hazard stripes, watermark, favicon tint, tab-title prefix)                                                           | The user wants distinct and "fancy" separators.                                                                               |
| D-008 | Data model          | **Profile → many marks.** A profile has URL patterns plus a list of marks. A mark targets the page or an element.                                                                              | No duplicated styles across similar URLs. Maps to how people think ("Production", "Staging").                                 |
| D-009 | Storage / privacy   | **Local only** (`storage.local`), no sync. Moving data between devices uses **JSON import/export**.                                                                                            | Privacy-first. No accounts, no servers.                                                                                       |
| D-010 | Permissions         | No host access at install. Each origin is requested **at runtime** (`optional_host_permissions`) when a pattern is added. Content scripts are registered dynamically for granted origins only. | Smallest possible footprint and no scary install warning. Also works in Safari.                                               |
| D-011 | UI surfaces         | **Popup** (status, toggles, pick, hide) + **Options page** in a full tab (full management, import/export)                                                                                      | Side panels differ too much between browsers.                                                                                 |
| D-012 | Theme               | Neumorphic, **light + dark, follows the OS**, with a manual override                                                                                                                           | Accessible contrast and real focus rings are kept (neumorphism alone fails WCAG).                                             |
| D-013 | Injection isolation | Marks render in a **closed Shadow DOM overlay** (`pointer-events: none`) that follows the target. The page DOM and layout are never mutated.                                                   | Page CSS can't break marks, marks can't break the page, and SPA re-renders are handled by re-tracking.                        |
| D-014 | Languages           | **English + Dutch** at launch via `_locales` (i18n-ready for more)                                                                                                                             |                                                                                                                               |
| D-015 | Safari              | Build the `safari-mv3` target with WXT, then wrap it with `xcrun safari-web-extension-converter` on macOS (manual/CI macOS job). The App Store needs an Apple developer account.               |                                                                                                                               |
| D-016 | Multiple matches    | **All matching profiles apply.** Page-level marks stack by profile priority (user-reorderable). The popup lists each matching profile with its own toggle.                                     |                                                                                                                               |
| D-017 | Missing element     | Retry through a `MutationObserver` (SPAs, lazy content). If still missing, the popup shows "element not found" plus **Re-pick**. Nothing is shown on the page.                                 | No page-level noise.                                                                                                          |
| D-018 | Quick actions       | **Keyboard shortcut** to start the picker (`Alt+Shift+M`, remappable) and **temporarily hide marks** on the current tab (until reload/navigation)                                              | The toolbar badge and starter templates weren't selected and are listed under "Later" in the spec.                            |
| D-019 | Progress tracking   | Markdown task list in the repo (`docs/tasks.md`), linked to requirement IDs, plus `pnpm progress` for a traceability report                                                                    | Lives next to the code. Diffs show progress.                                                                                  |
| D-020 | Tests               | Vitest + React Testing Library (unit/component, happy-dom) + Playwright (e2e with the built extension in Chromium). Firefox/Safari get a manual smoke checklist.                               |                                                                                                                               |
| D-021 | Tooling / license   | pnpm, MIT                                                                                                                                                                                      |                                                                                                                               |
| D-022 | Brand               | Logo: bookmark ribbon + pointer cursor on a soft tile. Accent: **signal coral/red**.                                                                                                           | Coral says "caution, production". The ribbon is the "Mark" and the cursor is the picker.                                      |
| D-023 | Design deliverables | Design tokens (`src/styles/tokens.css`) + `docs/design.md` in the repo                                                                                                                         |                                                                                                                               |
| D-024 | Process             | Spec-driven (spec → plan → tasks), then **TDD red → green → refactor** per task. Implementation starts **only when the owner says so**.                                                        |                                                                                                                               |

## Decisions I made as defaults (open for challenge)

| ID    | Topic               | Default                                                                                                                                                                                               |
| ----- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-101 | Content-script tech | Plain TypeScript + DOM (no React) in content scripts, to keep the injected bundle tiny (budget ≤ 25 KB gzip). React is only used in the popup and options page.                                       |
| D-102 | Validation          | `zod` schemas for stored data and imports.                                                                                                                                                            |
| D-103 | Storage API         | WXT `storage.defineItem` (built-in versioning + migrations).                                                                                                                                          |
| D-104 | Messaging           | `@webext-core/messaging` (typed, from the WXT author).                                                                                                                                                |
| D-105 | Selector generation | `@medv/finder` with custom filters that prefer `id`/`data-testid`/ARIA attributes and reject hashed class names. The result must resolve to exactly one element.                                      |
| D-106 | Permission fallback | Request permissions from the popup/options (user gesture). If the browser closes the popup during the prompt (Firefox), open `grant.html` in a tab instead.                                           |
| D-107 | E2E permissions     | E2E builds (`SITEMARK_E2E=1`) pre-grant `*://*.sitemark.test/*` because Playwright can't click native permission prompts. Fake hosts resolve to the local fixture server via `--host-resolver-rules`. |
| D-108 | Top layer           | Put the overlay host in the top layer with the Popover API (`popover="manual"`) where supported, so page `<dialog>`s and popovers don't hide marks. Otherwise fall back to max `z-index`.             |
| D-109 | Print               | Marks are hidden when printing (`@media print`).                                                                                                                                                      |
| D-110 | UI language         | Follows the browser's UI language (standard `_locales` behavior). An in-app language override is listed under "Later".                                                                                |
