## Plan review 2026-09-25: owner decisions

| ID    | Topic                  | Decision                                                                                                                                                                                                            |
| ----- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-201 | "Mark this site"       | Creates a site group named after the host, with pattern `*://<host[:port]>/*` and **one blue ribbon whose text is the host name**. It doesn't guess the environment; the user renames and restyles the group.       |
| D-202 | Naming                 | **Site group** in the UI, the docs **and the code** (`SiteGroup`). One vocabulary everywhere, and no clash with browser "profiles".                                                                                 |
| D-203 | Defaults               | New site groups get **a ribbon only**. Banner, frame, title prefix, favicon and so on are opt-in (the title prefix also ends up in browser history).                                                                |
| D-204 | Popup controls         | No global enable switch in the popup. The popup offers **Hide on this tab**; groups are enabled and disabled in settings.                                                                                           |
| D-205 | Palette                | Colorblind-safe presets **red `#c93a2e`, amber `#f4a300`, blue `#1f6feb`, slate `#57606a`** + custom hex. Ribbon and banner text is mandatory, so color is never the only cue.                                      |
| D-206 | Multi-match selector   | An element mark applies to the **first** matching element only.                                                                                                                                                     |
| D-207 | Hide duration          | Hiding lasts until **reload, leaving the origin, or closing the tab**, and survives in-app (SPA) route changes. The state lives in content-script memory (no `storage.session`, no `tabs` permission).              |
| D-208 | Hide shortcut          | A second command, `toggle-hide`, with **no default key** (the user assigns one).                                                                                                                                    |
| D-209 | Merge strategy         | **Rebase-merge** only. Squash and merge commits are disabled. `git bisect` skips red commits.                                                                                                                       |
| D-210 | TDD enforcement        | **Automated.** CI checks that red comes before green and that red actually failed. Task status comes from git. A REQ counts as covered only by a **passing** test that names it.                                    |
| D-211 | Regex                  | **Safe subset only:** no backreferences, lookaround or nested quantifiers (validated with `regexpp`). A regex only runs after its origin prefilter matches, and only on URLs of 2048 characters or fewer.           |
| D-212 | Broad patterns         | **Forbidden.** No `*` host and no `*.<public suffix>` such as `*.com` or `*.co.uk`. A host must be a registrable domain, an IP address or `localhost`.                                                              |
| D-213 | Safari                 | Ships in **v1.1** (milestone M9), minimum **Safari 18** on macOS. v1.0 is Chromium + Firefox. The `safari-mv3` build stays in CI so it keeps working.                                                               |
| D-214 | Firefox automation     | A **manual checklist** each release. No Firefox e2e suite.                                                                                                                                                          |
| D-215 | Fullscreen / top layer | Marks stay **on top**, including over fullscreen elements and page dialogs. The host is moved back to the top whenever the top layer changes.                                                                       |
| D-216 | Scope                  | **Everything stays in v1**, including the polish the lead added. Every v1 requirement is Must except the two Could items, which stay in v1 as the last tasks of their milestone.                                    |
| D-217 | Favicon                | **Tint the original only.** If it can't be read (CORS / tainted canvas), the favicon is left unchanged and the popup shows "favicon tint unavailable". The request goes to the site itself; PRIVACY documents this. |
| D-218 | Import clashes         | The same ID means **update the existing group** (upsert). Local settings are kept on merge.                                                                                                                         |
| D-219 | Silent failures        | A **toolbar badge "!"** on each tab where a matching group can't fully render (element missing, favicon unavailable, read-only data).                                                                               |
| D-227 | Publishing             | **Automated `wxt submit`** in `release.yml`, only on protected `v*` tags, inside the GitHub Environment `store` with a required reviewer. The job that builds the zips has no secrets.                              |
| D-228 | Versioning             | **Changesets.** User-facing PRs add a changeset, and the version and CHANGELOG are generated from them.                                                                                                             |

## Plan review 2026-09-25: engineering (owner accepted the reviewer consensus)

| ID    | Topic                  | Decision                                                                                                                                                                                                                                                                                                                   |
| ----- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-220 | Single writer          | The **background is the only writer** of `storage.local`. Other contexts send **commands or intents**, and the background applies them in a serialized queue (`applyCommand` in core, then `revision` + 1). Nothing else ever saves the whole state.                                                                       |
| D-221 | Need-to-know           | A content script only receives a **render plan** for its own URL, pushed by the background, and never the full state. Where supported, `storage.local.setAccessLevel('TRUSTED_CONTEXTS')` is set.                                                                                                                          |
| D-222 | Layers & ports         | `core ← app ← platform / content / ui / shared ← entrypoints`. `app` holds use cases and ports, and `platform` implements the ports. WXT **auto-imports are disabled**. Enforced by ESLint zones, a DOM-free core tsconfig and a node test env for core. _Lint tool superseded by D-243 (Biome zones)._                    |
| D-223 | Mark model             | `Mark = PageMark \| ElementMark`, discriminated by target. Effects are a keyed record per target type, so page-only effects can't exist on elements. Opacities are integer percents, IDs are branded, and there are no timestamps (YAGNI). Turning an effect off deletes its settings.                                     |
| D-224 | Data lifecycle         | One core pipeline, `migrate(unknown) → Result<State>`, for both storage **and** imports, on plain `storage.local` (supersedes D-103). A newer schema opens in **read-only mode**. Unreadable data is kept in 3 rotating backups.                                                                                           |
| D-225 | Errors                 | Core never throws on user input: it returns `Result<T, E>` with error codes. Adapters convert rejections into typed errors. One `errorMessageKey(code)` maps codes to i18n. A `Logger` port adds the `[SiteMark]` prefix.                                                                                                  |
| D-226 | Shadow mode            | The build constant `__SHADOW_MODE__` is `closed` in production and `open` in test/e2e builds, because Playwright can't pierce closed roots. A test asserts production uses `closed`.                                                                                                                                       |
| D-229 | Permission flow        | `permissions.request` is called **first and synchronously** in the click handler. The background completes the flow on `permissions.onAdded`: it syncs registration and injects into open tabs. `grant.html` is the fallback for any context that can't prompt (a popup that closes, the in-page panel). Supersedes D-106. |
| D-230 | Allowed page mutations | Exactly three reversible mutations: the `<sitemark-root>` host node, `document.title` (opt-in prefix) and the favicon `<link>` (opt-in). Everything else lives inside the shadow root. Supersedes D-013.                                                                                                                   |
| D-231 | Registration sync      | `syncRegistration()` is single-flight and idempotent, diffed against `getRegisteredContentScripts`, and runs on **every** background start as well as on events. `excludeMatches` is never used. Safari's persistence is treated as a cache only.                                                                          |
| D-232 | Shadow styles          | Prefer `adoptedStyleSheets`, which the page's CSP can't block. Feature-detect, and fall back to a `<style>` element (needed for Firefox bug 1751346 until the minimum version includes the fix).                                                                                                                           |
| D-233 | Test layers            | Vitest projects: `core` (node), `dom` (happy-dom) and `browser` (Vitest browser mode in Chromium, for layout, canvas, popover and selectors). Playwright e2e covers real extension behavior. The e2e build has its own outDir and pre-grants only `prod.` and `test.sitemark.test`.                                        |
| D-234 | M0.5 hardening         | A hardening milestone before any feature work: TS flags, `imports:false`, type-aware lint with layer zones, Vitest projects, browser fakes, an e2e build mode, CI and supply-chain hardening, progress v2, verify-tdd and git hooks. _Lint tool: D-243._                                                                   |
| D-235 | Code conventions       | Named exports only (except WXT entrypoints). No barrel files. kebab-case `.ts` files, PascalCase `.tsx` components. Files ≤ 200 lines, functions ≤ 40 lines, cognitive complexity ≤ 15. `import type`. Exhaustive `switch` + `assertNever`. No enums. Details in `docs/conventions.md` (T-027).                            |
| D-236 | CSS                    | CSS Modules for React components. Only tokens and base primitives are global. Stylelint enforces tokens for color, background and shadow.                                                                                                                                                                                  |
| D-237 | Git hooks              | lefthook. Pre-commit runs prettier + eslint on staged files, with **no tests**, so red commits can still be committed. Commit-msg runs commitlint with a task-scope rule. CI runs the same checks. _Pre-commit tools superseded by D-243 (Biome + Prettier for Markdown/YAML)._                                            |
| D-238 | Supply chain           | Actions pinned by SHA, `persist-credentials: false`, job timeouts. pnpm `strictDepBuilds` + `minimumReleaseAge`. Dependabot groups minor/patch updates and uses a cooldown. Exact Node version in `.nvmrc`. zod `jitless`. No `eval` or `new Function` in the built output.                                                |
| D-239 | Threat model           | Content scripts and pages are **untrusted**; the background is the authority. **Non-goal:** a hostile site can always hide, spoof or detect marks. SiteMark prevents _accidental_ confusion; it is not a security control.                                                                                                 |
| D-240 | Picker input           | **Glass pane.** The picker covers the viewport with its own top-layer element, finds targets with `elementsFromPoint`, captures focus in its shadow root and only accepts `isTrusted` events, so the page never receives picker input.                                                                                     |
| D-241 | Browser floors         | Chrome/Edge ≥ 120 (Brave, Opera, Arc best-effort), Firefox desktop ≥ 140, Safari macOS ≥ 18 (v1.1). No Firefox Android or iOS. The floors are declared in the manifest.                                                                                                                                                    |
| D-242 | Composition            | The stacking rules in spec §5.2 are normative. **One banner per edge** (texts merged as `A · B`). Each ribbon corner goes to the highest-priority group. Z-order: frame < stripes < watermark < tint < banner < ribbon.                                                                                                    |

## M1+ implementation (lead, for owner review)

| ID    | Topic              | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| ----- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-258 | Core errors & IDs  | Error codes are camelCase string-literal unions per area (`src/core/errors.ts`); the i18n key is derived as `error${Capitalize<code>}` (no map), and numeric limits are written into the message text. `IdGen` has one typed method per kind; `IdGen` and `Clock` live in `core/ids.ts` and the app ports reuse them. Test doubles, builders and fast-check arbitraries live in `src/core/testing/`.                                                                                                                                                                                                                                                            |
| D-259 | User text & schema | `cleanText` strips `\p{Cc}\p{Cf}\p{Cs}\p{Zl}\p{Zp}` and trims (so ZWJ emoji sequences split). Lengths are UTF-16 `.length` (like `maxlength`). Numeric effect fields are integers (px too). `parseState` also rejects duplicate IDs anywhere in the state. Stored regex origins must be the URL engine's canonical `OriginPattern` (no port, never broad; spec §7 updated).                                                                                                                                                                                                                                                                                     |
| D-260 | URL engine         | Broad = `*.`+public suffix, a `*` host, `<all_urls>`; exact single-label hosts (`intranet`) are allowed. The suffix list is every single-label TLD plus a curated list (≈35 ccTLD second levels + 13 hosting platforms such as `github.io`). Pattern ports compare with the URL's effective port. Patterns are stored canonical (lowercase punycode host, percent-encoded path). Origin patterns never carry a port.                                                                                                                                                                                                                                            |
| D-261 | Regex safety       | D-211 as written still admitted catastrophic regexes. In addition to no backrefs/lookaround/nested quantifiers: alternation inside a quantifier with max > 1 is rejected, and a static backtracking-cost estimate (`regex-cost.ts`, budget 10⁷ steps, unanchored regexes charged 2048 start positions) rejects slow shapes. Regexes compile with the `u` flag and run unanchored on the URL without its fragment. Stored regexes are re-validated before matching.                                                                                                                                                                                              |
| D-262 | Commands           | Commands are a `type`-discriminated union validated structurally by `commandSchema`; semantic limits live in the reducers so the user gets typed codes. `applyCommand` bumps `revision` by 1 and re-parses the result (`commandProducedInvalidState` guards reducer bugs). New site groups (and duplicates) are created **disabled** at the bottom; duplicates are named `name.slice(0,35) + " copy"`. `updatePattern`/`updateExclude` edit in place (no transient auto-disable). Removing the last pattern returns the `siteGroupAutoDisabled` notice. `markThisSite` always adds a new group (top-right ribbon, host cut to 16 chars, name = host cut to 40). |
| D-263 | Render plan        | `RenderPlan` is plain JSON, sorted by `z`, keyed `${markId}:${effect}` (merged banners `banner:top                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | bottom`). Element marks stack between page tint and banner. Frames carry `insetPx`. `diffPlan.remove`carries the previous items (so document effects can strip).`compose`pulls in the URL engine and runs only in the background;`render-plan.ts`/`diff-plan.ts` are content-safe. The popup list (`matchingGroups`) ignores `enabled` and excludes. |
| D-264 | Data pipeline      | Newer data → `stateReadOnly` (raw kept untouched, every save refused, re-checked on each save so it survives SW restarts); unreadable → `stateUnreadable` → raw copied into 3 rotating backups (oldest `savedAt` replaced), defaults used, state key only overwritten by the next successful save. Import: ≤ 1 MiB UTF-8, nesting ≤ 32 pre-scanned, every pattern/exclude re-validated (`importPatternInvalid` with paths) and stored canonical. **Merge** upserts by ID, re-mints colliding IDs and keeps local settings; **Replace** takes the file's settings. Export JSON ends with a newline.                                                              |
| D-265 | Website build      | No `index.html` template: a React `Document` renders the page and prerender adds the doctype. Only pages that exist are prerendered. The website translator merges the website catalog with the extension catalog; pages receive `t`/`tp` as props. No `@vitejs/plugin-react` (full reloads in dev). verify-tdd treats website test infrastructure like the root's.                                                                                                                                                                                                                                                                                             |
| D-266 | Mutation testing   | Stryker 10 on `src/core` (excluding `testing/` and the public-suffix data), break 60; nightly job without cache (≈16 min). First full run: 89.7 %.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
